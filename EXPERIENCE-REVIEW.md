# Southern Luxury Glass experience makeover

Date: October 26, 2026. Branch: `codex/storefront-experience-20261026`.

## Brief and baseline
Kevin requested a full functions/features/motion makeover while keeping the current colors and style. Audience: antique and vintage glassware collectors. Primary journey: browse → inspect → save or inquire → Crystal arranges an invoice. Existing Next.js 14.2 / React 18 / Tailwind 3 / Prisma stack remains.

Baseline source: `origin/main` at `fd265dd`; existing checkout was clean and matched GitHub. Live baseline: https://southernluxuryglass.vercel.app/. The dated Brain note pointed to an old Downloads path; current source was verified at `C:/Users/WKBon/Projects/crystals-glass-store`. Work is isolated under Documents/Codex.

Confirmed defects and opportunities:

| Before | After | Why |
|---|---|---|
| Each favorite hook updated only itself; the browser storage event does not fire in its own tab | Same-tab change event, latest-list reads, and session fallback | Cards, gallery count and navigation agree immediately |
| Navigation heart opened the unfiltered gallery | Saved collection deep link and same-route state update | Saved means saved, including after a reload |
| Search omitted maker/era and matched untrimmed input | Normalized multi-term search across product metadata | Find pieces without knowing the exact title |
| No sort or available-only filter | Price/name/arrival sorting, composed filters and result count | Browse a collection deliberately |
| Empty result gave only a sentence | Clear recovery action and filter reset | Keep the visitor in the browsing journey |
| Photo overlay offered only arrows | Fit/zoom, thumbnails, keyboard, swipe, load-error retry | Inspect condition and detail before inquiring |
| Modal setup could initially focus a hidden honeypot and did not lock scrolling | Visible-focus filtering, nested-dialog stack, Escape, focus containment and scroll lock | Reliable keyboard/mobile dialogs |
| Timed signup interrupted the page with a modal | Nonmodal invitation; signup modal only after engagement | Preserve browsing and typing |
| Inquiry lacked a visual piece reminder | Existing product photo and price in inquiry | Make the inquiry context clear without implying purchase |
| Many product controls were under 44px | Larger control targets and mobile-safe viewport/input rules | Easier touch use without changing the visual world |

## Practical trial and selection
Representative sample: gallery → save → saved collection → photo viewer → inquiry. Mandatory criteria: preserve palette/type/photos; keep the invoice-only workflow; support keyboard and 320px phone width; no new paid services, UI libraries, database mutations or real test messages.

A baseline-to-refinement trial was used. Competing visual identities were not fabricated because replacing the identity would contradict the brief. The existing-components approach was the clear fit; new gallery generation, a new component library or a motion framework would add cost without resolving the observed bugs.

| Dimension (equal weight, 0–4) | Baseline | Refinement | Evidence |
|---|---:|---:|---|
| Task clarity/usability | 2 | 3 | Saved and inquiry journeys exercised |
| Hierarchy/legibility | 2 | 3 | Explicit control labels and mobile collapsed refinements |
| Brand/audience fit | 4 | 4 | Existing tokens, fonts and imagery retained |
| Accessibility/adaptation | 2 | 3 | Keyboard focus, 320/390/768/1440px checks, reduced motion |
| Visual craft | 3 | 3 | Palette and card treatment preserved |
| Behavior/performance | 2 | 3 | Actual frontend interaction checks; hardware frame performance unverified |
| Implementation fit | 3 | 4 | Existing React/CSS primitives; no new dependencies |

These are structured design judgments, not conversion evidence or accessibility certification.

Selected workflow: Design Overhaul for assessment; Impeccable for preserving/refining the existing interface and hardening states; Emil/Animate for bounded feedback and overlay timing; Mobile Native for viewport/touch rules; Playwright for actual interaction checks. Impeccable context ran against GalleryGrid and its requested mechanical scan returned `[]`. No new dependencies or hosted generation were used.

Other approaches reviewed for fit include 21st review/build/explore, Transitions.dev and React Bits. They were not installed or invoked as replacement UI systems. Taste-style art-direction changes conflict with the pinned identity; GSAP, video, 3D, image generation, logo packages and document/presentation workflows do not solve this storefront's current needs.

## Verification
Eight unit tests cover filtering, metadata search, sold/reserved exclusion, sort immutability, URL round-trips, malformed parameters and empty collections. Forty-two end-to-end browser assertions cover same-page favorites, saved-link navigation/reload, search/reset/sort, photo controls, focus restoration, background scroll lock, simulated inquiry failure/retry, responsive overflow, reduced motion and nonmodal signup. Additional checks cover keyboard focus containment and browser-storage-disabled operation.

Lint and TypeScript checks pass. A production-mode Next build succeeded using the local public-data fixture. That fixture never ships: the original `src/lib/prisma.ts` was restored byte-for-byte and checked in the final diff. The existing `npm run build` includes database migrations, so it was deliberately not used for UI testing. No migrations, schema changes, inventory writes, customer lookups or live form submissions were performed.
